# Лабораторная работа №4 — Парное программирование
## Проект: SpreadScope

### Задача
Доработка UI модуля спредов:
- фильтрация по биржам (gate / mexc / ourbit)
- сортировка таблицы по Spread % (↓ / ↑)

---

## 1) Какую задачу реализовывали?
Реализовали улучшения пользовательского интерфейса для просмотра спредов:
- добавили чекбоксы выбора бирж, влияющие на список отображаемых спредов
- добавили переключаемую сортировку по проценту спреда
- проверили работу фильтрации и сортировки на реальных данных из backend API

---

## 2) Какие стили парного программирования использовали?

### 2.1 Ведущий–ведомый (Driver / Navigator)
Реализовали UI и обработку выбранных бирж (checkbox + обновление данных).

### 2.2 Пинг-понг (Ping-Pong)
Шаги:
1) Участник 1 сформулировал проверки/кейсы сортировки (ожидаемое поведение).
2) Участник 2 реализовал сортировку и переключение направления.
3) Роли сменились для проверки edge-cases и финальной правки.

---

## 3) Какой стиль показался более приемлемым? Почему?
Более удобным оказался стиль Ведущий-ведомый, потому что код получается более корретным и оптимальным за счет проверки второго участника, из минусов то что занимает больше времени

---

## 4) Что получилось? Положительные впечатления
- Быстро нашли и закрыли edge-cases (пустой выбор бирж → показывать все)
- Логика сортировки стала прозрачнее благодаря “тестовым” кейсам в ping-pong
- Меньше ошибок из-за постоянной проверки вторым участником
- Улучшили читаемость кода за счёт совместного обсуждения

---

## 5) Что не получилось? Как можно поправить?
Сложностей как таковых небыло.

Как оптимизировать\улучшить:
- заранее согласовывать формат кода и именование
- менять роли по таймеру (каждые 10–15 минут)
- фиксировать acceptance criteria до начала кодинга
- использовать совместное редактирование (Live Share) или общий экран

---

## 6) Будем ли использовать ПП дальше? Для каких задач?
Да, парное программирование полезно для:
- сложных частей логики (нормализация пар, расчёт спредов, refactoring)
- архитектурных изменений (слой репозиториев, разделение polling/API)
- внедрения авторизации и персональных данных (watchlist/history/journal)
